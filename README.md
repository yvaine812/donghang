# 航旅智慧营销决策台 · 双端版（Demo）

## 运行（一条命令，两个入口）

```
pip install -r requirements.txt
python app.py
```

浏览器打开：

| 入口 | 地址 | 使用者 |
|---|---|---|
| 入口选择页 | http://127.0.0.1:7860/ | — |
| **客户侧：结伴出游模拟器** | http://127.0.0.1:7860/customer/ | 客户：输入需求 → 提取 → 核对修改 → 确认提交 |
| **内部侧：航旅智慧营销决策台** | http://127.0.0.1:7860/internal/ | 营销人员：市场洞察 / 客户需求 / 旅客画像 / 智能营销 / 效果评估 |

换端口：`PORT=8000 python app.py`。Demo 未做登录，正式使用请为 /internal 加访问控制。

## 数据流

客户 → 结伴出游模拟器 → 自然语言 → AI需求提取（原文依据＋置信度）→ 客户确认 → 结构化需求（data/customer_requests.json）→ 决策台“客户需求”页 → **群体层市场信号 ＋ 个体层客户需求** → 动态旅客画像 → 3～5条候选航线 → 规则筛选 → 触达决策 → AIGC内容 → 人工审核 → 模拟触达 → 效果评估 → 反馈。

- 客户侧只显示“您的出游需求已生成并提交”，不显示任何内部市场数据或营销判断。
- 内部侧的“客户需求”页读取客户真实提交的需求，点击【导入并分析】即进入画像与智能营销（先点【刷新客户需求】或重新打开页面）。
- 智能营销页保留“内部手动录入”，用于测试/电话咨询场景。

## 目的地筛选（只有两轮）

data/A成员数据搜集表(1).md（最新版）→ 第一轮粗筛（平台榜单＋平台共识＋可行性；抖音/微博/热词为辅助与留痕）→ 8～12个候选 → 第二轮百度指数精筛 → **最终候选目的地池** → 决策台。决策台运行时只读最终候选池，不会因客户请求重读原始热词表。【更新市场数据】重算整条链路，并显示更新时间、更新次数、候选池数量和成功/失败。

目的地未指定时，从最终候选池按（出发城市、航线可行性、假期、热度/趋势、预算、人数、兴趣、决策阶段）生成3～5条国内优先候选航线，不随机、不补齐；不足3条提示“候选不足”。指定目的地则直接分析该航线。
